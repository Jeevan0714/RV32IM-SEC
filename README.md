# 🛡️ RV32IM-SEC: Secure RISC-V Processor with Hardware Memory Scrambling

[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)
[![ISA: RV32IM](https://img.shields.io/badge/ISA-RV32IM-red.svg)](https://riscv.org/)

[![Waveform: GTKWave](https://img.shields.io/badge/Waveform-GTKWave-orange.svg)](http://gtkwave.sourceforge.net/)
[![Target PDK: SkyWater_130nm](https://img.shields.io/badge/PDK-SkyWater_130nm-purple.svg)](https://github.com/google/skywater-pdk)

**RV32IM-SEC** is an open-source, 32-bit **Secure IoT Processor System-on-Chip (SoC)** implemented in Verilog HDL. It combines a 5-stage pipelined **RV32IM RISC-V CPU core** with a hardware **Memory Scrambling Engine** powered by an integrated **Grain-128 Pseudo-Random Number Generator (PRNG)**.

Every byte written to physical RAM is dynamically XOR-encrypted on-the-fly using cryptographic keystreams generated by a dual LFSR/NFSR hardware engine. Physical eavesdroppers or attackers probing memory buses see only encrypted garbage, while the CPU seamlessly reads back decrypted plaintext in real time.

## 🌟 Executive Summary & Beginner Primer

> **New to VLSI or Computer Architecture? Start here!**

### 🧠 What is a RISC-V Core?
A **CPU core** is the central brain of an embedded chip. It reads code instructions (like `ADD`, `SUB`, `MULTIPLY`, `LOAD`, `STORE`) and executes them. **RISC-V** (pronounced *"risk-five"*) is an open-standard Instruction Set Architecture (ISA) used worldwide for everything from tiny microcontrollers to high-performance AI chips.

### 🔍 Why do we need Memory Scrambling?
In conventional microcontrollers, when the CPU writes data to RAM (such as secret keys, passwords, or sensor readings), the data travels over copper wires across the chip in plain text. 

An attacker with physical access to the device can attach tiny oscilloscope probes to these memory traces (a **physical probing attack** or **bus-tapping attack**) or freeze the RAM chip (a **cold boot attack**) to extract confidential data.

### 🛡️ How RV32IM-SEC Solves This
1. **On-the-Fly Scrambling**: When the CPU writes `0x0000000C` to RAM, our hardware engine XORs the data with a continuous 32-bit pseudorandom keystream produced by a **Grain-128 stream cipher algorithm** (driven by non-linear and linear feedback shift registers).
2. **Scrambled Physical Storage**: Physical RAM stores `0x8181818D` (random noise).
3. **Transparent Decryption**: When the CPU reads back from RAM, the scrambler XORs the stored data with the exact same keystream bitmask, restoring `0x0000000C` instantly.
4. **Zero Software Overhead**: The CPU core and software programs run normally without knowing encryption is happening beneath them!

## 🚀 Key Features

- **Standard RISC-V RV32IM ISA Support**: Supports basic 32-bit integer instructions (`RV32I`) plus hardware multiplication and division extensions (`M-Extension`: `MUL`, `DIV`, `REM`).
- **5-Stage In-Order Pipeline**: Divided into **Fetch (IF)**, **Decode (ID)**, **Execute (EX)**, **Memory (MEM)**, and **Writeback (WB)** stages for high clock throughput.
- **Full Hazard Resolution**:
  - **Data Forwarding Unit**: Resolves RAW (Read-After-Write) hazards without stalling execution.
  - **Hazard Detection Unit**: Generates automatic pipeline stalls and flushes for load-use hazards and branch mispredictions.
- **Grain-128 PRNG Core**: 
  - Integrated 128-bit Linear Feedback Shift Register (**LFSR**) and 128-bit Non-Linear Feedback Shift Register (**NFSR**).
  - High-entropy, crypto-grade non-linear boolean keystream generation.
- **On-the-Chip Memory Protection**:
  - Transparent hardware memory scrambler interposed between CPU memory bus and physical SRAM.
  - Memory-mapped address decoder for modular SoC bus expansion.

## 🔒 Verification & Security Proof

During simulation of the Phase 4 Secure SoC, the processor executes a program compiled from RISC-V assembly that writes the plaintext value `0x0000000C` (decimal 12) into memory location 100.

### Simulation Output
```text
━━━ Compiling Phase 4: Secure SoC ━━━
iverilog -o sim/phase4/sim_soc -g2012 ...
━━━ Running simulation ━━━
vvp sim/phase4/sim_soc

---------------------------------------------------------
MEMORY SECURITY VERIFICATION
---------------------------------------------------------
The CPU wrote the plaintext value: 0x0000000C to address 100
Physical RAM [address 100] holds : 0x8181818D
Current PRNG Keystream           : 0xB1B1B1B1
---------------------------------------------------------
SUCCESS: Physical data is safely scrambled!
```

- **CPU View (Software Level)**: Sees `0x0000000C`
- **Bus Keystream**: `0xB1B1B1B1`
- **Physical RAM (Hardware Level)**: `0x0000000C ⊕ 0xB1B1B1B1 = 0x8181818D` (Unreadable ciphertext!)

To simulate and verify this project on Linux (Ubuntu/Debian), install the required open-source EDA tools:

## 📖 Key Terms & Glossary for Beginners

| Term | Full Name | Explanation |
| :--- | :--- | :--- |
| **RTL** | Register-Transfer Level | The hardware design code written in Verilog that defines how data moves between logic gates and registers. |
| **Testbench** | Simulation Test Harness | A non-synthesizable Verilog module that feeds clock, reset, and stimulus inputs into the processor to check if it works. |
| **Pipelining** | Pipeline Execution | Splitting instruction execution into stages (like an assembly line) to increase throughput. |
| **Hazard** | Data/Control Hazard | A situation where the next instruction cannot execute in the current clock cycle (e.g., waiting for data from a previous instruction). |
| **PRNG** | Pseudo-Random Number Generator | A deterministic hardware circuit that generates unpredictable sequences of bits for cryptography. |
| **LFSR / NFSR** | Linear / Non-Linear Feedback Shift Register | Digital shift registers with feedback taps used as fundamental building blocks in hardware ciphers like Grain-128. |
| **GDS-II** | Graphic Data System II | The final binary file format sent to a semiconductor foundry (e.g., TSMC, SkyWater) to fabricate physical silicon chips. |
